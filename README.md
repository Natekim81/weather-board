# 현장 일정 날씨판

오늘 현장 일정과 지역별 날씨를 한 화면에서 보고, 날씨 때문에 주의 · 중지를 검토할 일정을 표시합니다. (교육용 가상 데이터)

## 여는 법
- 배포 주소(HTTP/HTTPS)로 열면 `data/tasks.json`에서 기본 일정을 읽습니다.
- 내 PC에서 `index.html`을 더블클릭해 JSON을 읽지 못하면 ‘배포 주소로 열어 주세요’를 표시합니다. 이때 기본 일정은 표시되지 않고, 브라우저의 추가 일정은 읽을 수 있는 경우 표시됩니다.
- 인터넷 : (배포 후 Vercel 주소를 여기에 적기)

## 파일

## 오늘 날씨 (F-04)
- 키가 필요 없는 [Open-Meteo 예보 API](https://open-meteo.com/en/docs)를 사용합니다. 인터넷 연결이 필요합니다.
- 세종·대전·태안·보령의 대표 좌표로 한국 시간(`Asia/Seoul`) 기준 오늘 하루 예보를 요청합니다.
- 일별 최고 기온(`temperature_2m_max`), 최대 풍속(`wind_speed_10m_max`, `wind_speed_unit=ms`), 최대 강수확률(`precipitation_probability_max`)을 표시합니다.
- 실내는 항상 ‘영향 없음’입니다. 나머지는 고소 강풍(10 m/s 이상) → 폭염(33℃ 이상) → 우천(60% 이상) 순서로 하나만 표시하고, 해당 사항이 없으면 ‘진행’입니다.
- 지역별 요청은 10초 후 중단합니다. 실패하거나 예보 값이 누락된 지역은 날씨 ‘-’, 판단 ‘날씨 확인 전’으로 표시하며 목록과 일정 추가는 계속 사용할 수 있습니다. 실내 판단은 ‘영향 없음’입니다.

## 확인 방법
- **T-01**: 배포 주소로 열어 JSON의 기본 일정 6건이 표시되는지 확인합니다. 이전에 추가한 일정은 그 뒤에 표시됩니다. JSON 분리에 따라 기존 PRD의 더블클릭 확인 방법을 변경합니다.
- **T-02**: 가상 일정을 추가해 맨 아래에 보이는지, 새로고침 후에도 남는지 확인합니다. 날씨 수신 후 추가한 일정에도 해당 지역의 날씨와 판단이 표시됩니다.
- **T-03**: 인터넷에 연결한 상태로 열어 4개 지역의 최고 기온·최대 풍속(m/s)·강수확률과 판단을 확인합니다. 같은 지역 일정은 같은 날씨를 사용합니다. 실제 예보에 따라 지역 간 일부 값은 같을 수 있습니다.
- **T-04**: 브라우저 주소 끝에 `?test=wind`를 붙여 엽니다 (`index.html?test=wind`). 모든 지역의 풍속이 12 m/s로 표시되고 기본 고소 일정 2건이 ‘중지 검토’인지 확인합니다. 상단에 시험값 안내가 표시됩니다. API 실패 시에도 풍속만 시험값으로 표시하고, 기온·강수확률은 ‘미수신’으로 남깁니다. 시험을 끝내려면 쿼리 문자열을 제거합니다.
- **T-01·T-03 실패 상황**: `?test=wind`를 제거하고 개발자 도구에서 날씨 API 요청만 차단한 뒤 새로고침합니다. JSON 일정 목록은 유지되고, 상단에 실패 지역이 표시되며 실외 일정은 ‘날씨 확인 전’, 실내 일정은 ‘영향 없음’인지 확인합니다.
- **T-05**: 추가 일정을 저장한 뒤 `data/tasks.json`의 가상 일정 이름을 바꾸어 배포하고 새로고침합니다. 기본 일정에는 JSON 변경이 반영되고, 추가 일정은 맨 뒤에 유지되는지 확인합니다. 개발자 도구의 Local Storage `wx_added`에는 추가 일정만 있어야 합니다.
- **T-06**: `index.html`을 더블클릭해 JSON 읽기가 차단되면 ‘배포 주소로 열어 주세요’가 보이는지 확인합니다. 배포 주소에서 JSON 요청이 실패하면 파일 읽기 실패 안내가 표시됩니다. 날씨 상태 갱신이나 일정 추가로 안내가 사라지지 않아야 합니다.
- **T-07**: ‘오늘 판단 md로 저장’을 눌러 `현장일정_판단_YYYY-MM-DD.md`가 내려받아지는지 확인합니다. 날짜는 한국 시간 기준입니다. 파일을 열어 현재 표의 6개 열과 추가 일정이 같은 순서로 들어 있고, 맨 아래 판단 기준에 풍속 10 m/s·강수확률 60%·기온 33℃가 있는지 확인합니다. 날씨 미수신 상태와 `?test=wind`에서도 현재 표가 저장되며, 시험 모드에서는 시험값 안내가 포함됩니다. 일정 이름에 `|`, 줄바꿈, `<` 등이 있어도 Markdown 표가 유지되는지 확인합니다.

## 일정 데이터
- 기본 일정은 `data/tasks.json`에만 둡니다. 앱은 이 파일의 요청과 해석이 끝난 뒤 `wx_added`에서 추가 일정을 읽어 뒤에 합칩니다.
- 화면에서 일정을 추가할 때 JSON은 다시 요청하지 않고, 추가 일정만 브라우저에 저장합니다. 기존 `wx_added`의 추가 일정도 유지합니다.
- JSON은 일정 객체의 배열이며 각 객체에는 `title`, `region`, `kind`, `owner` 문자열이 필요합니다. 지역과 구분은 화면의 선택 목록과 같아야 합니다.
- JSON을 읽지 못하면 기본 일정을 코드나 브라우저 저장 목록으로 대체하지 않습니다. 브라우저의 추가 일정만 표시합니다.
